# BOSCH Plasma-Etching Dataset — NetCDF Structure

Generated by inspecting the raw `.nc` files with `h5py`.

> **Note on paths:** there is no `data/raw/` directory in this project. All `.nc`
> files live directly in the project root. Paths below are relative to the root.

All four kinds of `.nc` file are **netCDF-4 (HDF5 backed)**, written with
netcdf 4.9.2 / hdf5 1.14.x. The only global attribute is `_NCProperties`.

## Key encoding scheme (important)

Both `data` variables are stored as **`uint16` indices**, *not* physical values.
The actual float values are recovered by indexing into the matching dictionary
file:

```python
import h5py
codes = h5py.File("Day_2024_07_02.nc")["Wafer_01/data"][:]      # uint16
table = h5py.File("Dictionary_OES.nc")["data"][:]               # float32
values = table[codes]                                           # physical units
```

This is a lossy scalar-quantisation codec: the dictionary is a sorted float32
codebook, and every measurement is replaced by the index of its nearest
codebook entry. It is what keeps a 14744 x 3648 spectrum array under 1 GB.

| Dictionary | Length | Value range | Used by |
|---|---|---|---|
| `Dictionary_OES.nc` | 61 443 | −323.576 … 7782.856 | `Day_*.nc` `data` |
| `Dictionary_process.nc` | 49 290 | −103.580 … 3426.923 | `Process_data.nc` `data` |

Observed index ranges stay inside the table bounds (OES max 49 288 of 61 443;
process 118 … 49 283 of 49 290), consistent with the index interpretation.

## `Dictionary_OES.nc` / `Dictionary_process.nc`

Flat codebooks, no groups.

**Dimensions**
- `x` = 61443 (OES) / 49290 (process) — _dimension only, no coordinate variable_

**Variables**

| name | dtype | shape | dimensions |
|---|---|---|---|
| `data` | float32 | (61443,) OES / (49290,) process | `x` |

No variable attributes. Values are monotonically increasing.

## `Day_YYYY_MM_DD.nc` — OES spectra

Structure verified on `Day_2024_07_02.nc`; the other Day files follow the same
layout (only the time extent differs).

**Root:** 10 groups, `Wafer_01` … `Wafer_10`. No root-level variables.

### Group `/Wafer_NN`

**Dimensions**
- `time` = 14744 (varies per wafer) — _dimension only, no coordinate variable_
- `wavelength` = 3648 — _dimension only, no coordinate variable_

**Variables**

| name | dtype | shape | dimensions | storage |
|---|---|---|---|---|
| `data` | uint16 | (time, 3648) | time, wavelength | chunked (4915, 1216), gzip |
| `times` | float64 | (time,) | time | chunked, gzip |
| `wavelengths` | float64 | (3648,) | wavelength | chunked, gzip |

**Attributes of `times`**
- `units`: `seconds since 1970-01-01 00:00:00 UTC`
- `calendar`: `standard`

`data` and `wavelengths` carry no attributes.

**Axis details**
- `wavelengths`: 185.891 … 883.967 nm, ~0.1914 nm/pixel, 3648 pixels
  (a typical 3648-element CCD spectrometer).
- `times`: genuine Unix epoch seconds. Wafer_01 spans
  2024-07-02 12:23:00.936 → 12:33:48.968 UTC, ~0.0440 s/sample (≈22.8 Hz),
  ≈11 min per wafer.

**Per-wafer `data` shapes in `Day_2024_07_02.nc`**

| group | shape | group | shape |
|---|---|---|---|
| `Wafer_01` | (14744, 3648) | `Wafer_06` | (14856, 3648) |
| `Wafer_02` | (15178, 3648) | `Wafer_07` | (14961, 3648) |
| `Wafer_03` | (14765, 3648) | `Wafer_08` | (15036, 3648) |
| `Wafer_04` | (14805, 3648) | `Wafer_09` | (14707, 3648) |
| `Wafer_05` | (15108, 3648) | `Wafer_10` | (14839, 3648) |

## `Process_data.nc` — machine sensor traces

**Root:** 96 groups named `Day_YYYY_MM_DD_Wafer_NN`, covering **10 days**
(more days than the 5 Day OES files present locally). No root-level variables.

### Group `/Day_YYYY_MM_DD_Wafer_NN`

**Dimensions**
- `time` = ~3200–3900 (varies per wafer) — _dimension only, no coordinate variable_
- `feature` = 44 or 31 (varies per day) — _dimension only, no coordinate variable_

**Variables**

| name | dtype | shape | dimensions |
|---|---|---|---|
| `data` | uint16 | (time, feature) | time, feature |
| `times` | float64 | (time,) | time |

**Attributes of `times`**
- `units`: `seconds since 1970-01-01 00:00:00 UTC`
- `calendar`: `standard`

`data` carries no attributes.

**Group coverage**

| day | wafers | `feature` | `time` range |
|---|---|---|---|
| `Day_2024_07_02` | 01–10 | **44** | 3245–3298 |
| `Day_2024_07_05` | 01–10 | 31 | 3245–3299 |
| `Day_2024_07_09` | 01–10 | 31 | 3195–3349 |
| `Day_2024_07_11` | 01–10 | 31 | 3194–3351 |
| `Day_2024_07_19` | 01–10 | 31 | 3195–3351 |
| `Day_2024_08_01` | 01–10 | 31 | 3245–3299 |
| `Day_2024_08_05` | 01–**06** | 31 | 3245–3299 |

## Caveats found during inspection

1. **`Process_data.nc` `times` are NOT epoch timestamps** despite the
   `seconds since 1970-01-01` attribute. `Day_2024_07_02_Wafer_01` starts at
   92.77 s, i.e. these are *relative* seconds from process start. The OES
   `times` in the `Day_*.nc` files *are* true epoch seconds. Do not join the
   two on raw `times` without correcting this.
2. **`feature` count is not constant.** `Day_2024_07_02` has 44 channels, every
   other day has 31. Any code stacking process data across days must align
   channels rather than assume a fixed width. **The 31-channel set is a clean
   subset of the 44** — the 07/02 day simply carries 13 extra sensors
   (`Gas6Flow`, `Heater5..8Temp`, `ThermoCouple1..4Temp`,
   `SourceRFLoadCapacitor`, `SourceRF2LoadCapacitor`, `attenuatorRatio`,
   `moriOuterCurrent`) — so aligning to the common 31 names is trivial.
3. **Feature names ARE stored** (corrected 2026-08-08 by opening the file with
   `netCDF4`). Each group has a variable-length **string** variable
   `feature` (shape `(n_feature,)`) holding channel names like
   `Stat3_Etch_MV_Gas1Flow`, `Stat3_Etch_MV_SourceRFLoadPower`. The earlier
   "unlabelled" note came from an `h5py` inspection that did not surface the
   vlen-string variable; read `grp["feature"][:]` via `netCDF4` as the Readme
   snippet shows.
4. **Day file / process file coverage differs.** `Process_data.nc` covers 10
   days, but only 5 `Day_*.nc` OES files are present here.
5. **`Day_2024_08_05` has 6 wafers**, not 10.
6. `time` / `wavelength` / `x` are pure netCDF dimensions with no coordinate
   variable; they appear as zero-length HDF5 dimension scales. The usable
   coordinate arrays are `times` and `wavelengths`.

## Quick-start snippet

```python
import h5py, numpy as np

oes_table = h5py.File("Dictionary_OES.nc")["data"][:]

with h5py.File("Day_2024_07_02.nc") as f:
    g = f["Wafer_01"]
    wl = g["wavelengths"][:]           # (3648,) nm
    t  = g["times"][:]                 # (n,) epoch seconds
    spec = oes_table[g["data"][:100]]  # first 100 frames -> physical values
```
